## 📝 Описание лабораторной работы

Лабораторная работа посвящена разработке **автоматизированной информационной системы (АИС) для автосалона** на языке PHP с использованием базы данных SQLite.

Целью работы является создание полноценного веб-приложения с разграничением прав доступа (обычный пользователь / администратор), реализацией CRUD-операций для управления каталогом автомобилей, системой регистрации и аутентификации пользователей, а также возможностью отправки заявок на приобретение автомобиля.

**Основные задачи:**
- Разработать систему регистрации и входа пользователей с хранением хешированных паролей.
- Реализовать каталог автомобилей с возможностью поиска и фильтрации.
- Создать административную панель для управления данными.
- Обеспечить безопасность приложения: валидацию входных данных, защиту от SQL-инъекций (PDO Prepared Statements), экранирование вывода (XSS-защита).

## 🚀 Инструкции по запуску проекта

### Требования

| Компонент | Версия     |
|-----------|------------|
| PHP       | ≥ 7.4      |
| SQLite    | встроен в PHP |
| Веб-сервер | Apache / Nginx / встроенный PHP-сервер |

Убедитесь, что в PHP включено расширение `pdo_sqlite`:
```bash
php -m | grep pdo_sqlite
```

### Вариант 1 — Встроенный PHP-сервер (рекомендуется для разработки)

```bash
# 1. Клонируйте или распакуйте проект
git clone <url-репозитория>
cd autosalon

# 2. Запустите встроенный веб-сервер PHP
php -S localhost:8000

# 3. Откройте браузер по адресу
# http://localhost:8000
```

### Вариант 2 — Apache (XAMPP / WAMP / LAMP)

```bash
# Скопируйте папку autosalon/ в корневую директорию сервера:
# XAMPP (Windows): C:\xampp\htdocs\autosalon
# LAMP  (Linux):   /var/www/html/autosalon

# Убедитесь, что директория data/ доступна для записи:
chmod 755 autosalon/data/
```

Откройте в браузере: `http://localhost/autosalon`

### Права на директорию с базой данных

```bash

```

## 🗄️ Структура базы данных

База данных SQLite состоит из трёх таблиц.

### Таблица `users` — пользователи

| Поле            | Тип     | Описание                                |
|-----------------|---------|-----------------------------------------|
| `id`            | INTEGER | Первичный ключ, автоинкремент           |
| `name`          | TEXT    | Имя пользователя                        |
| `email`         | TEXT    | Email (уникальный)                      |
| `password_hash` | TEXT    | Хеш пароля (bcrypt через `password_hash()`) |
| `role`          | TEXT    | Роль: `user` или `admin`               |
| `created_at`    | TEXT    | Дата и время регистрации                |

### Таблица `cars` — автомобили

| Поле           | Тип     | Описание                                     |
|----------------|---------|----------------------------------------------|
| `id`           | INTEGER | Первичный ключ, автоинкремент                |
| `brand`        | TEXT    | Марка автомобиля (например, BMW)            |
| `model`        | TEXT    | Модель (например, 320d)                     |
| `year`         | INTEGER | Год выпуска (1980 — текущий год)            |
| `price`        | REAL    | Цена в евро                                 |
| `fuel_type`    | TEXT    | Тип топлива: `Petrol`, `Diesel`, `Hybrid`, `Electric` |
| `transmission` | TEXT    | КПП: `Manual` или `Automatic`              |
| `description`  | TEXT    | Текстовое описание                          |
| `created_at`   | TEXT    | Дата добавления                             |

### Таблица `requests` — заявки

| Поле         | Тип     | Описание                                          |
|--------------|---------|---------------------------------------------------|
| `id`         | INTEGER | Первичный ключ, автоинкремент                    |
| `user_id`    | INTEGER | Внешний ключ → `users(id)`                       |
| `car_id`     | INTEGER | Внешний ключ → `cars(id)`                        |
| `message`    | TEXT    | Текст сообщения от пользователя                  |
| `created_at` | TEXT    | Дата и время отправки заявки                     |

### ER-диаграмма (текстовое представление)

```
users (id, name, email, password_hash, role, created_at)
   │
   │ 1:N
   ▼
requests (id, user_id, car_id, message, created_at)
                            │
                        N:1 │
                            ▼
              cars (id, brand, model, year, price,
                    fuel_type, transmission, description, created_at)
```

## 💡 Примеры использования

### Пример 1: Подключение к базе данных

Функция `getDb()` в `src/db.php` возвращает PDO-объект:

```php
// src/db.php
function getDb(): PDO
{
    $dbPath = __DIR__ . '/../data/database.sqlite';
    $pdo = new PDO('sqlite:' . $dbPath);
    $pdo->setAttribute(PDO::ATTR_ERRMODE, PDO::ERRMODE_EXCEPTION);
    return $pdo;
}
```

### Пример 2: Поиск автомобилей с фильтрацией (search.php)

Динамическое построение SQL-запроса с использованием Prepared Statements:

```php
$sql = "SELECT * FROM cars WHERE 1=1";
$params = [];

if ($brand !== '') {
    $sql .= " AND brand LIKE ?";
    $params[] = '%' . $brand . '%';
}
if ($fuel !== '') {
    $sql .= " AND fuel_type = ?";
    $params[] = $fuel;
}
if ($minPrice !== '') {
    $sql .= " AND price >= ?";
    $params[] = $minPrice;
}

$stmt = $pdo->prepare($sql);
$stmt->execute($params);
$cars = $stmt->fetchAll(PDO::FETCH_ASSOC);
```

### Пример 3: Защита страниц через middleware-функции (src/auth.php)

```php
function requireAdmin(): void
{
    if (!isAdmin()) {
        header('Location: /login.php');
        exit;
    }
}

// Использование в любом файле админки:
requireAdmin(); // если не администратор — редирект на /login.php
```

### Пример 4: Защита вывода от XSS (src/auth.php)

```php
function e(string $text): string
{
    return htmlspecialchars($text, ENT_QUOTES, 'UTF-8');
}

// В шаблоне:
<h3><?= e($car['brand']) ?> <?= e($car['model']) ?></h3>
```

### Пример 5: Хеширование и проверка пароля

```php
// Регистрация — сохранение хеша:
password_hash($password, PASSWORD_DEFAULT)

// Вход — проверка пароля:
if ($user && password_verify($password, $user['password_hash'])) {
    $_SESSION['user'] = [
        'id'    => $user['id'],
        'name'  => $user['name'],
        'email' => $user['email'],
        'role'  => $user['role']
    ];
    header('Location: profile.php');
}
```

### Пример 6: Валидация данных автомобиля (src/validation.php)

```php
function validateCar(array $data): array
{
    $errors = [];

    if (trim($data['brand'] ?? '') === '') {
        $errors[] = 'Введите марку автомобиля.';
    }
    if (!isset($data['year']) || !filter_var($data['year'], FILTER_VALIDATE_INT)) {
        $errors[] = 'Год выпуска должен быть числом.';
    } elseif ($data['year'] < 1980 || $data['year'] > date('Y')) {
        $errors[] = 'Год выпуска указан некорректно.';
    }
    // ...

    return $errors;
}
```

## ❓ Ответы на контрольные вопросы

**1. Что такое PDO и зачем оно используется в проекте?**

PDO (PHP Data Objects) — это универсальный интерфейс для работы с базами данных в PHP. В проекте PDO используется для подключения к SQLite. Главное преимущество — поддержка **подготовленных запросов (Prepared Statements)**, которые полностью исключают SQL-инъекции, так как пользовательские данные передаются отдельно от SQL-кода.

**2. Как реализована аутентификация пользователей?**

Аутентификация реализована через PHP-сессии (`$_SESSION`). При успешном входе в `$_SESSION['user']` сохраняются `id`, `name`, `email` и `role`. Каждая защищённая страница вызывает функцию `requireLogin()` или `requireAdmin()`, которая проверяет наличие и корректность данных сессии. Пароли хранятся в виде bcrypt-хешей с помощью функций `password_hash()` и `password_verify()`.

**3. Как устроена система ролей?**

В таблице `users` есть поле `role` с возможными значениями `user` и `admin`. Функции `isLoggedIn()` и `isAdmin()` в `src/auth.php` проверяют это поле в активной сессии. На основании роли отображаются или скрываются элементы навигации, а защищённые маршруты администратора защищены вызовом `requireAdmin()` в начале каждого файла.

**4. Как база данных создаётся и заполняется начальными данными?**

Файл `src/init.php` подключается на каждой странице через `require_once`. При первом запуске он выполняет `CREATE TABLE IF NOT EXISTS` для всех трёх таблиц. Если таблица `users` не содержит администратора — он создаётся автоматически. Если таблица `cars` пуста — добавляются три тестовых автомобиля. Таким образом, проект не требует ручного запуска SQL-скриптов.

**5. Каким образом реализована защита от XSS-атак?**

Весь пользовательский контент перед выводом в HTML пропускается через функцию `e()`, которая вызывает `htmlspecialchars()` с флагами `ENT_QUOTES` и кодировкой `UTF-8`. Это преобразует специальные символы `<`, `>`, `"`, `'`, `&` в HTML-сущности, не позволяя браузеру интерпретировать их как код.

**6. Какой метод шифрования паролей применяется?**

Используется алгоритм **bcrypt** через встроенные PHP-функции `password_hash($password, PASSWORD_DEFAULT)` и `password_verify()`. Bcrypt автоматически добавляет соль (salt) к каждому хешу, что делает атаки по радужным таблицам неэффективными. Константа `PASSWORD_DEFAULT` гарантирует использование наилучшего доступного алгоритма в текущей версии PHP.

**7. Как реализован поиск автомобилей?**

Поиск построен на динамическом формировании SQL-запроса в `search.php`. Базовый запрос начинается с `SELECT * FROM cars WHERE 1=1`, к которому по условию добавляются фильтры: `LIKE` для поиска по марке, точное совпадение для типа топлива, `>=` и `<=` для диапазона цен. Все параметры передаются через Prepared Statements, что защищает от инъекций.

**8. Какова структура MVC-подобного разделения кода в проекте?**

Проект не использует строгий MVC-фреймворк, однако логика разделена по уровням: директория `src/` содержит многократно используемые функции (подключение к БД, аутентификация, валидация), что играет роль слоя «Model/Service». PHP-файлы в корне и `admin/` совмещают роль «Controller» (обработка запросов) и «View» (генерация HTML). Это типичный подход для учебных PHP-проектов.

## 📌 Дополнительные замечания

### Безопасность

- Все SQL-запросы используют **Prepared Statements** — защита от SQL-инъекций.
- Весь вывод экранируется через `htmlspecialchars()` — защита от XSS.
- Пароли хранятся только в виде bcrypt-хешей, никогда в открытом виде.
- Доступ к административным страницам проверяется на каждой странице через `requireAdmin()`.

### Ограничения текущей реализации

- Заявки пользователей (`requests`) доступны только через прямые SQL-запросы; в административной панели их отображение не реализовано.
- Приложение не предусматривает редактирование профиля или смену пароля пользователем.
- Отсутствует пагинация каталога при большом количестве автомобилей.

### Возможные улучшения
